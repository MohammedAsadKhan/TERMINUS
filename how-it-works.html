Agentic SOC — the pipeline

How it works

Seven stages from raw log to resolved incident. The agent does the busywork; an engineer makes the final calls.

The pipeline

Each stage hands off to the next — and only the irreversible actions stop for a human.

1
The vulnerable service

A deliberately vulnerable Apache server runs in a VM as the bait — the thing an attacker would hit.

Apache VM bridged network
2
Wazuh SIEM ingests logs

Wazuh collects endpoint and web logs. Our policies flag suspicious activity — brute force, webshell uploads.

Wazuh detection rules
3
Agent dispatched

A policy hit dispatches an AI agent to investigate the incident within a set timeframe.

opencode agent runtime OpenCode Go
4
Investigation

The agent queries the Wazuh API, correlates related events, enriches indicators via VirusTotal, and maps behavior to MITRE ATT&CK.

Wazuh API VirusTotal MITRE ATT&CK
5
Decision engine

Reversible actions auto-execute. Irreversible actions queue for an engineer's approval.

policy engine human-in-the-loop
6
Actions fire

A Jira ticket is created, the engineer is notified via Slack / PagerDuty / SMS, and lockdown runs after approval.

Human in the loop

Autonomy scales with reversibility — the more destructive the action, the more it waits for a person.

Tier 1 · Autonomous

Read-only

Enrichment, context gathering, correlation, report drafting. No side effects — runs with no approval.

Tier 2 · Auto-execute

Reversible writes

Tickets, notifications, blocking a single IP. Safe to undo, so the agent just does it.

Tier 3 · Human approval

Irreversible

Host isolation, account disablement. High blast radius — waits for an engineer to approve.

~70% of organizations already run this “AI recommends, human approves” model — only ~14% let AI act unsupervised.
