# Disposable Wazuh lab acceptance

Team LARP | COSC 3370 | Package version 0.1.0 | November 14, 2026

This procedure is for the isolated SSH response scenario only. The November 13 evidence proves one run on the existing local Docker lab. A fresh ZIP install has passed API acceptance, but a second full Wazuh build and approved response from that extracted copy has **not** yet passed. Preserve that distinction when presenting the result.

## Inputs and boundaries

- Windows Docker Desktop with Linux containers, at least 4 CPU cores, 8 GB memory, and 50 GB available Docker storage, per [Wazuh's single-node Docker requirements](https://documentation.wazuh.com/current/deployment-options/docker/wazuh-container.html). Use a disposable NTFS-backed Docker data location. Keep management ports bound to loopback; the two lab networks carry the integration and attack traffic privately.
- The [official Wazuh Docker single-node stack](https://documentation.wazuh.com/current/deployment-options/docker/wazuh-container.html), pinned to `v4.14.10`, with generated test certificates. The Wazuh stack is third-party software and is not included in the TERMINUS source ZIP.
- A fresh TERMINUS source ZIP extraction, `uv sync --frozen`, PowerShell, `ssh-keygen`, and a browser. The prebuilt TERMINUS console needs no Node installation.
- A unique 32+ character Wazuh source key and a stable local token secret in the private TERMINUS lab `.env`. Keep credentials, generated certificates, SSH keys, databases, and Docker volumes outside the source ZIP.

## Bring up and check

1. Follow the official Wazuh single-node certificate and startup instructions. Before starting, bind any host-published manager, indexer, and dashboard ports to `127.0.0.1`. Confirm `single-node_default` exists and the three Wazuh services are healthy. Record the actual port mapping and Wazuh agent ID; do not assume the previous lab's `002` persists.
2. From `audit-output/lab/response-target` in the extracted ZIP, run `./setup.ps1`, then `docker compose up -d --build`. Confirm target, attacker, and observer containers are healthy and that the target agent is Active in Wazuh. The endpoint command is installed from `scripts/lab/terminus_ip_block.py` with an LF shebang. [The lab harness README](../audit-output/lab/response-target/README.md) records the exact topology and independent observer stages.
3. Create `audit-output/lab/terminus/.env` locally with `TERMINUS_DEPLOYMENT_MODE=local`, `TERMINUS_HOST=0.0.0.0` (inside the container only), `TERMINUS_PORT=8000`, `TERMINUS_WAZUH_WEBHOOK_ORG=org-terminus-demo`, `TERMINUS_WAZUH_WEBHOOK_KEY=<unique secret>`, `TERMINUS_TOKEN_SECRET=<stable secret>`, `TERMINUS_RESPONSE_AGENT_ID=<observed agent ID>`, and `TERMINUS_RESPONSE_AGENT_MANAGEMENT_IP=<target management IP>`. For the opt-in worker, also set `TERMINUS_RESPONSE_ACTOR=<current administrator user ID>`, `TERMINUS_RESPONSE_API_USER`, `TERMINUS_RESPONSE_API_PASSWORD`, and `TERMINUS_RESPONSE_INDEXER_PASSWORD`. The Compose host port remains `127.0.0.1:8000`.
4. Set `TERMINUS_SOURCE_ROOT` in the launching PowerShell to the absolute extracted source directory, using forward slashes for the Windows drive path. From `audit-output/lab/terminus`, run `docker compose config --quiet`, then `docker compose up -d --build`. The image pins `uv`; the service installs from `uv.lock` into its persistent volume before becoming healthy. Confirm `http://127.0.0.1:8000/health` and `/console/`, sign in with the disposable local account, and verify the incident list has no seeded presentation records.
5. Install `scripts/lab/custom-terminus` in the Wazuh manager and add the block in [the integration example](wazuh_integration.xml) to its `ossec.conf`, using the same source key. The `terminus` hostname resolves only on the private shared Docker network. Restart the manager and confirm the integration loads without a script error.
6. Generate three failed SSH attempts with `docker exec response-attacker /usr/local/bin/attack.sh 3`. Record the raw Wazuh agent/rule/event IDs and timestamps, the authenticated `/sources/wazuh` receipt, its hash and tenant, and TERMINUS's offline/unknown analysis mode. Do not call the alert itself proof of an attack beyond these test attempts.
7. From the same TERMINUS Compose directory and shell, run `docker compose --profile response up -d response-worker` only after the API, target, attacker, observer, Wazuh manager and indexer are healthy. Recheck the target's current management IP and update `TERMINUS_RESPONSE_AGENT_MANAGEMENT_IP` before creating the worker; Docker can assign a different address after restart. This worker shares the database, reads the private lab credentials from `.env`, mounts only the observer script and generated SSH key, and runs independently of the API process. Its Compose command explicitly passes `--insecure-lab-tls` for the generated self-signed certificates; the worker accepts this exception only with the Docker observer and fixed internal Wazuh lab URLs. Other worker invocations verify TLS certificates by default. Check its logs for the independent baseline and readiness message. It does **not** auto-restart after a host reboot: that previously caused repeated baseline failures while the target was stopped. Startup alone authorizes no action. In the Response tab, review the exact source, target, evidence IDs, duration and proposal digest. A separate administrator approval must match that digest.
8. Observe and preserve five distinct states: authorization recorded, durable intent, Wazuh acknowledgement, independent `verified_blocked` (attacker denied, management SSH healthy, exact owned set/source present), then independent `recovered` (attacker restored, management healthy, set empty). Acknowledgement alone never passes. The disposable target's 30-second maintenance loop then scans a bounded nftables inventory and deletes only expired, empty tables whose full comment matches their derived name and expected lab structure. Wait for its cleanup record, then run the independent observer's `table-absent` stage; a successful delete command alone is not proof. Run denied approval, protected IP, missing sensor, duplicate delivery, interrupted worker, and unknown effect checks; record each result as executed or unverified.
9. Stop the response worker, TERMINUS Compose, response-target Compose, and Wazuh stack. Check for remaining owned nftables tables and reconcile any ambiguous intent. Keep raw evidence redacted and separate from credentials. A production supervisor and alerting plan remain unverified.

## Acceptance decision

The disposable demo is a GO only if the fresh extraction reproduces the authenticated source alert and exact authorized block/recovery with independent evidence, automatic empty-table removal confirmed by the separate observer, and safe negative cases. The cleanup loop has fixture tests but has not been exercised in a fresh Wazuh cycle. Worker supervision, repeated acceptance, backup/restore, static-analysis clearance, tenant review, and measured analyst benefit remain production gates. Record failures as failures, including provider HTTP 200 with no endpoint effect.
